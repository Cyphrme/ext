# Traversal

How `ext` walks a registered root: which entries it hashes, which it skips,
and what happens when a root disappears.

## File types

- **Regular files** are hashed.
- **Directories** are walked. The store directory is never walked, and a
  sub-extant is walked only when it is itself registered (see the README).
- **Symlinks** are never followed and never hashed. A registered root whose
  path contains a symlink is refused, because the link could later be pointed
  somewhere else.
- **Device files, FIFOs and sockets** are never opened. Opening a FIFO blocks
  until a writer appears, and reading a device can block forever or have side
  effects.

Skipped entries are counted and reported, never silently dropped.

## Mounts

The walk enters other mounted filesystems, so registering `/` covers the
whole system. It does not descend into virtual filesystems, whose contents
are generated by the kernel or held only in memory: `proc`, `sysfs`,
`devtmpfs`, `devpts`, `tmpfs`, `ramfs`, `cgroup`, `cgroup2`, `debugfs`,
`tracefs`, `securityfs`, `pstore`, `bpf`, `configfs`, `fusectl`, `mqueue`,
`hugetlbfs`, `binfmt_misc`, `efivarfs` and `autofs`. A root that is itself
registered on one of these is walked.

## Read errors

A file or directory that cannot be read is reported and keeps its existing
index entries. The scan continues.

## Deleted roots

A registered root can disappear because it was deleted, or because the disk
it lives on is not mounted. The two cases are handled differently:

- **Deleted.** The root no longer exists, and its nearest existing ancestor
  is on the same filesystem the root was on when it was last scanned. The
  root is unregistered and its entries are removed, and this is reported. A
  config option disables this, so that a deleted root is only reported.
- **Missing mount.** The root's filesystem is not the one recorded: the root
  is missing and its nearest existing ancestor is on a different filesystem,
  or the root exists but is on a different filesystem (an empty mountpoint).
  The root is refused, its entries are kept, and `ext` exits non-zero.

`ext unregister` and `ext register` on the root are the explicit ways to
forget it or to accept its new filesystem.
